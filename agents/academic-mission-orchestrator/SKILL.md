# SKILL — Academic Mission Orchestrator

## 1. Mission intake

Create a mission record with:

- objective;
- institution/program;
- target intake;
- current date;
- candidate constraints;
- current documents;
- known deadlines;
- funding dependency;
- relocation dependency;
- current research concept;
- current supervisor/lab targets.

Do not put sensitive candidate facts in a public repository. Load them privately at runtime.

## 2. Call-for-applications audit

Extract:

- application window;
- eligibility;
- required files;
- file-size/format rules;
- anonymous-review rules;
- affirmative-action rules;
- scoring weights;
- phase-specific minimums;
- interview criteria;
- supervisor selection rules;
- proficiency requirements;
- enrollment dates;
- appeal windows;
- disqualification clauses.

Output:

- `Call Matrix`;
- `Elimination Risks`;
- `Deadline Calendar`;
- `Document Upload Map`.

## 3. Candidate evidence audit

For each candidate claim, identify the best evidence.

Never use memory or a previous summary where an original document is available.

Output:

- evidence ledger;
- contradictions;
- missing documents;
- documents that should not be used.

## 4. Barema engine

For each scoring item:

1. quote/paraphrase the official rule;
2. determine point value and cap;
3. match candidate evidence;
4. calculate defensible points;
5. label uncertain interpretations;
6. compute phase mathematics.

Always show scenarios when acceptance of an item is uncertain.

## 5. Research proposal audit

Review against both the official rubric and scientific standards.

Minimum checks:

- research gap is real;
- question is answerable;
- objective matches design;
- sample size rationale matches study type;
- randomization/controls are operationally plausible;
- primary outcomes are explicit;
- exploratory technology cannot sink the thesis;
- intervention is reproducible;
- safety and adverse-event procedures exist;
- ethics and data governance are adequate;
- statistics match sample/design;
- timeline is sequential and realistic;
- recruitment and staffing are credible;
- references are real/current/relevant;
- no candidate identification when anonymous review is required.

## 6. Supervisor/lab fit

Use public evidence only.

Map:

- supervisor's research history;
- lab methods/equipment;
- current projects;
- relevant publications;
- software/instrumentation culture;
- training environment;
- whether the candidate adds a new application/population/method.

Never claim interest, supervision, or funding without direct evidence.

## 7. Communication guardian

Before drafting/sending:

- role conflict check;
- timing check;
- selection-phase check;
- minimum necessary content;
- no pre-grading request;
- no privileged-information request;
- no scholarship guarantee request;
- test-of-the-committee: would this look legitimate if made public to the whole committee?

## 8. Scholarship engine

Create a separate scholarship state.

Track:

- eligibility;
- employment status declaration language;
- lab participation;
- supervisor consent;
- CV scoring;
- quota availability;
- implementation;
- payment timing;
- residence obligations;
- renewal conditions.

## 9. Relocation engine

Do not start with apartments. Start with constraints:

- date physical presence is required;
- cash on hand;
- scholarship implementation status;
- temporary housing option;
- distance to campus;
- expected monthly budget;
- deposit and setup costs;
- fallback if first payment is late.

## 10. Mission update

Every major update should answer:

- What changed?
- What is now verified?
- What gate moved?
- What new risk appeared?
- What is the single highest-leverage next action?
